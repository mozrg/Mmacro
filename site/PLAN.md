# План сайта Mmacro

Статус: реализовано 13.11.2026. Сайт лежит в `site/`, публикация на хостинг ещё не выполнялась.

## 1. Задача

Сделать отдельный статический сайт Mmacro в папке `site/`.

Обязательный минимум:

- прямое скачивание актуальной версии без промежуточных страниц;
- просмотр версии: номер, дата, что изменилось и скачивание конкретного релиза.

Сайт не дублирует панель макроса и не пытается запускать AutoHotkey в браузере. Его задача — объяснить, что делает Mmacro, дать требования, быстро скачать нужную версию и посмотреть историю изменений.

## 2. Что будет на сайте

### Главная страница

1. **Шапка**
   - логотип и название Mmacro;
   - навигация: «Возможности», «Установка», «Версии», «Discord»;
   - компактная плашка текущей версии;
   - кнопка скачивания.

2. **Первый экран**
   - название и одна понятная фраза о продукте;
   - главная кнопка `Скачать 1.0.13` — прямая ссылка на архив;
   - вторая кнопка `Все версии`;
   - строка с фактами: последний релиз, дата, Windows, AutoHotkey v1.1;
   - справа — визуальный образ панели Mmacro / карты с слотами, а не абстрактная иллюстрация.

3. **Возможности**
   - режимы `Infinite`, `Raid`, `Summer Event`;
   - расстановка юнитов по сохранённым слотам;
   - распознавание карты по заголовку;
   - Auto Upgrade;
   - автоголосование за карточки Summer Event;
   - Auto-Rejoin;
   - Discord-бот: `/screenshot`, `/runs`, `/maps`, `/map`.

4. **Быстрый старт**
   - скачать архив;
   - распаковать;
   - установить AutoHotkey v1.1;
   - запустить `macro/main.ahk`;
   - нажать `Embed` и настроить координаты.

5. **Требования**
   - Windows;
   - AutoHotkey v1.1, не v2;
   - Roblox Player;
   - игровая область `1280x720`;
   - интернет — для проверки обновлений и Discord-бота.

6. **Версии**
   - блок с последними тремя релизами;
   - ссылка на полную страницу версий.

7. **Частые вопросы**
   - Roblox не найден;
   - кнопки не нажимаются;
   - не определяется карта;
   - не выбираются карточки;
   - где лежат настройки;
   - как обновляться.

8. **Подвал**
   - Discord;
   - GitHub;
   - текущая версия;
   - предупреждение, что сторонние макросы могут нарушать правила игры, если это уместно для проекта.

### Страница версий

Отдельная страница `versions.html`:

- текущий релиз крупно: номер, дата, заметки, кнопка скачивания;
- история релизов от новых к старым, сейчас это 14 опубликованных релизов;
- для каждой версии — тег, дата, список изменений и прямая ссылка на архив;
- якорные ссылки вида `versions.html#1.0.13`;
- данные берутся из GitHub Releases API;
- при недоступности API показывается встроенный снимок данных, поэтому страница и скачивание не ломаются.

Релизы без заметок не выдумывают текст: показывается «Заметки не указаны». Теги без опубликованного релиза не смешиваются с релизами и не выдаются за проверенные сборки.

## 3. Прямое скачивание

Сейчас у релизов на GitHub нет прикреплённых файлов, только автоматически создаваемые архивы исходников. Поэтому:

- основная кнопка ведёт прямо на `https://github.com/mozrg/Mmacro/archive/refs/tags/<версия>.zip`;
- для каждого релиза используется свой тег;
- клик не ведёт на страницу релиза и не требует входа в GitHub;
- рядом с кнопкой явно указано, что скачивается ZIP с исходниками и какой это тег;
- не показываем выдуманный размер файла и не полагаемся на HTML-атрибут `download`: внешний GitHub его игнорирует;
- если позже к релизу прикрепят готовый ZIP, ссылку заменим на `releases/download/...` без переделки сайта.

Кнопка скачивания повторяется в шапке, на первом экране, после блока возможностей и на странице версий. Второстепенное действие всегда одно — «Все версии». Других равнозначных CTA рядом нет.

В репозиторий не коммитим ZIP-архивы. Это лишний вес и устаревшие копии.

## 4. Версия: откуда берётся истина

- Источник — опубликованные GitHub Releases, а не ветка `main`.
- Ближайший опубликованный релиз — `1.0.13` от 18 августа 2026.
- В `main` есть более новые коммиты без релизного тега. На сайте они не выдаются за стабильную версию: показываем «Последний релиз 1.0.13», а не «Последний коммит».
- Номер версии на сайте обновляется автоматически после публикации нового GitHub Release.
- Встроенный fallback хранит проверенные данные, чтобы при ошибке API не показывать пустой экран.

## 5. Визуальное направление

Не делать типовой тёмный лендинг с фиолетовыми градиентами, неоновым HUD и одинаковыми карточками.

Направление: **оперативная карта фарма, а не магазин игровых товаров**. Сайт выглядит как аккуратно изданное полевое руководство: светлая карта, тёмная панель управления, синие метки и редкие оранжевые предупреждения.

- Фон — прохладная светлая «бумага карты», не белая и не кремовая;
- один тёмный блок-панель в первом экране создаёт контраст с остальной страницей;
- структура — сетка карты, линии маршрута и метки слотов;
- главный визуальный элемент — реалистичный макет панели Mmacro рядом со схемой карты, а не абстрактная 3D-иллюстрация;
- крупная типографика для названия, спокойный плотный текст для инструкций;
- анимация — один короткий вход панели при загрузке; остальное реагирует только на действия пользователя;
- никакого неона, свечения, стекломорфизма, параллакса и декоративных градиентов;
- иконки — только SVG, без эмодзи.

### Логотип

Используются все три присланных варианта:

- прозрачный — в шапке и первом экране;
- тёмный — в макете панели, подвале и на тёмных блоках;
- синий — как основа для favicon и аватара.

### Токены

| Роль | Цвет | Использование |
|---|---|---|
| Фон карты | `#F1F4F2` | основной фон страницы |
| Поверхность | `#FFFFFF` | строки инструкций, таблица версий |
| Тёмная панель | `#0A0A0A` | макет панели, подвал |
| Основной текст | `#111C2E` | заголовки и основной текст |
| Вторичный текст | `#475569` | подписи, даты, пояснения |
| Логотип | `#3F83FB` | фирменный синий из логотипа |
| Светлая M | `#A8C5FF` | задняя буква логотипа |
| Основное действие | `#1D5FD1` | кнопки скачивания, контраст с белым 5.8:1 |
| Сигнал | `#EA580C` | только крупные метки и предупреждения |

### Типографика

- заголовки и номер версии: **Unbounded** 600/700, кириллица подтверждена;
- текст, подписи и элементы интерфейса: **Golos Text** 400/500/600, кириллица подтверждена;
- оба шрифта подключаются локальными WOFF2-файлами с лицензиями, без внешнего Google Fonts в рантайме;
- никакого монопространственного шрифта «для техничности»: цифры версий и дат используют табличные цифры Golos Text.

### Композиция

- первый экран делится асимметрично: слева заголовок и скачивание, справа панель на фрагменте карты;
- блок возможностей — не сетка одинаковых карточек, а «журнал операций»: крупные смысловые группы с разной шириной и одной общей сеткой;
- быстрый старт — горизонтальная последовательность с номерами, потому что это действительно шаги;
- страница версий — реестр релизов: широкие строки, текущий релиз выделен не только цветом, но и подписью; заметки видны сразу, без скрытых аккордеонов;
- футер — «легенда карты» с обозначениями версии, GitHub и Discord.

## 6. Технически

- Чистые HTML, CSS и JavaScript.
- Без сборки, npm и фреймворков: сайт открывается как файл и публикуется как статика.
- Один набор стилей и один скрипт.
- Локальные ассеты: логотип и favicon из `macro/logo/`.
- Данные версий — отдельный JS/JSON-файл с fallback.
- GitHub API вызывается только для обновления списка версий; скачивание работает и без него.
- Никакой авторизации, базы данных, аналитики и cookies.
- Ссылки на GitHub и Discord открываются в новой вкладке.

### Качество

- адаптивность на 320, 375, 768, 1024 и 1440 px;
- нажатия не меньше 44×44 px, hover не является единственным способом узнать о действии;
- клавиатурная навигация, заметный фокус, корректная иерархия заголовков и `aria`-подписи;
- контраст текста не ниже WCAG AA;
- поддержка `prefers-reduced-motion`;
- отсутствие горизонтального скролла и каруселей с автопрокруткой;
- семантическая разметка и корректные meta/Open Graph;
- быстрый первый экран без тяжёлых библиотек;
- `aria-current` для активного пункта навигации и ссылки на текущую версию;
- ошибка загрузки данных версий объясняется текстом, а не пустым блоком.

## 7. Чего в первой версии не будет

- личного кабинета и подписок;
- админки для редактирования версий;
- комментариев и рейтингов;
- встроенного запуска макроса;
- скачивания с собственного сервера;
- аналитики, рекламы и сбора данных;
- английской версии. Если понадобится — добавим после русской.

## 8. Публикация

Сайт можно открыть локально двойным кликом.

Для публикации предлагаю GitHub Pages через отдельный workflow, который отдаёт содержимое `site/`. GitHub Pages не умеет брать произвольную папку `site` напрямую, поэтому нужен workflow либо перенос в `docs/`. Это изменение вне `site/`, поэтому делаю только после отдельного подтверждения.

## 9. Найденная проблема, не входящая в сайт

В `macro/main.ahk` указан репозиторий `mozrze/Mmacro`, а реальный remote — `mozrg/Mmacro`. Встроенная проверка обновлений через GitHub API с этим значением, скорее всего, получает 404. Сайт это не блокирует, но после одобрения могу отдельно исправить строку.

## 10. Критерии готовности

- [x] папка `site/` содержит рабочую главную страницу;
- [x] кнопка скачивания отдаёт ZIP нужной версии прямым переходом;
- [x] страница версий показывает список релизов, заметки и даты;
- [x] при отключённом GitHub API страница остаётся рабочей;
- [x] нет битых ссылок и ошибок в консоли;
- [x] проверены мобильная и десктопная вёрстки;
- [x] проверены клавиатура и фокус;
- [x] проверено открытие сайта локально и через локальный HTTP-сервер.

Проверено в Edge: 390, 768 и 1440 px; горизонтального переполнения нет. Все 14 релизов отрисовываются, у каждого работает прямая ссылка на ZIP. Скриншоты проверялись через локальный сервер.

## 11. Что нужно от вас

Сайт готов к просмотру. Откройте `site/index.html` или запустите локальный сервер из корня репозитория:

```powershell
python -m http.server 4173 --directory site
```

Публикацию на GitHub Pages нужно подтвердить отдельно.
